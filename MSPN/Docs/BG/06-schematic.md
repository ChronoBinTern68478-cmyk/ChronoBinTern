# Схема

## 1. Общ преглед

MSPN изисква четири хардуерни компонента:

1. **μPC** — брояч на микропрограмата (адрес на текущата микростъпка)
2. **Мултиплексор за знака** — преобразува `{r, p, f}` в `{−1, 0, +1}`
3. **Акумулатор (ACC)** — регистър с отместване, събиране и изваждане
4. **Логика за управление** — декодира микростъпките и генерира сигналите

Потокът от битове се чете от отделна памет (ROM, RAM или
последователен вход) на адреса, зададен от μPC.

## 2. Блокова схема

```text
                ┌──────────────────┐
                │ Памет за         │
                │ управление       │
                └────────┬─────────┘
                         │ m ∈ {r,p,f}
                         ▼
                ┌──────────────────┐
                │       μPC        │◄──── нулиране / инициализация
                │  (нагоре/надолу) │
                └────────┬─────────┘
                         │ адрес
                         ▼
                ┌──────────────────┐
                │ Поток от битове  │
                │ (ROM/RAM/сериен) │
                └────────┬─────────┘
                         │ bit ∈ {0,1}
                         ▼
                ┌──────────────────┐
                │ Мултиплексор за  │
                │ знака             │
                │ r → −1            │
                │ p →  0            │
                │ f → +1            │
                └────────┬─────────┘
                         │ s ∈ {−1,0,+1}
                         │ bit ∈ {0,1}
                         ▼
                ┌──────────────────┐
                │   Умножител      │  s × bit
                │ (тривиално: AND) │
                └────────┬─────────┘
                         │ ±bit
                         ▼
                ┌──────────────────┐
                │   Акумулатор     │
                │ (отместване +    │
                │  събиране)       │
                └────────┬─────────┘
                         │
                         ▼
                    резултат V
```

## 3. μPC — брояч на микропрограмата

### 3.1 Предназначение

Съхранява адреса на текущата микростъпка. Задава адресите както на
паметта за управление, така и на паметта за потока от битове.

### 3.2 Поведение

| Микростъпка | Действие на μPC |
|---|---|
| `r` | μPC ← μPC − 1 |
| `f` | μPC ← μPC + 1 |
| `p` | изчаква 1 такт, след което μPC ← μPC + 1 |

### 3.3 Ширина

За вход от `n` бита μPC трябва да адресира `n+1` позиции
(каноничната форма NAF може да изисква още една позиция).
Минималната ширина е `ceil(log₂(n+1))` бита.

| n | Ширина на μPC |
|---:|---:|
| 1 | 2 |
| 4 | 3 |
| 8 | 4 |
| 16 | 5 |
| 32 | 6 |

### 3.4 Реализация

```text
┌─────────────┐
│  Регистър   │
│  (k бита)   │
└──────┬──────┘
       │ Q
       ▼
┌─────────────┐     ┌──────────┐
│  Суматор    │────►│  MUX     │
│  (+1/−1/0)  │     │          │
└─────────────┘     └────┬─────┘
       ▲                 │
       │                 ▼
┌──────┴──────┐    ┌─────────┐
│ Управление  │    │ Тактов  │
│  (r/f/p)    │    └─────────┘
└─────────────┘
```

**Сигнали:**

- `UP = 1`, ако `m = f`
- `DOWN = 1`, ако `m = r`
- `WAIT = 1`, ако `m = p`
- `LOAD = 1`, ако има нулиране или външна инициализация

**Логика:**

```text
if LOAD:      μPC ← init
elif WAIT:    μPC ← μPC   (задържане за 1 такт)
elif UP:      μPC ← μPC + 1
elif DOWN:    μPC ← μPC − 1
```

Забележка: при `p` броячът се задържа точно за един такт, след което
на следващия такт μPC се увеличава с 1. Това изисква малка машина на
състоянията или flip-flop `WAIT_DONE`:

```text
WAIT_DONE_next = (m == p) && !WAIT_DONE
μPC_next =
    if WAIT_DONE: μPC + 1
    elif m == p:  μPC
    elif m == f:  μPC + 1
    elif m == r:  μPC − 1
```

## 4. Мултиплексор за знака

### 4.1 Предназначение

Преобразува 2-битовия код на микростъпката в знакова 2-битова стойност.

### 4.2 Кодиране

| Микростъпка | 2-битов код | Стойност на знака (2 бита) |
|---|---|---|
| `p` | `00` | `00 (0)` |
| `f` | `01` | `01 (+1)` |
| `r` | `10` | `11 (−1)` |
| (запазен) | `11` | — |

### 4.3 Реализация

Таблица за съответствие 2 към 2 бита или директно:

```text
s[1] = m[1]                (знаков бит)
s[0] = m[1] XOR m[0]       (бит за модула, само при +1)
```

Или най-просто — ROM с 4 записа.

## 5. Умножител (s × bit)

### 5.1 Предназначение

Умножава знаковата 2-битова стойност по 1-битовия вход.
Тъй като битът е 0 или 1, операцията се реализира с елементарна логическа врата:

```text
±bit = s × b
```

### 5.2 Таблица на истинност

| `m` | `b` | `s` | `s × b` |
|---|---:|---:|---|
| `p` | 0 | 0 | 0 |
| `p` | 1 | 0 | 0 (невалидно според ограничението) |
| `f` | 0 | +1 | 0 (невалидно според ограничението) |
| `f` | 1 | +1 | +1 |
| `r` | 0 | −1 | 0 (невалидно според ограничението) |
| `r` | 1 | −1 | −1 |

При ограничението `b = 1 ⟺ m ∈ {r, f}` са възможни само 3 случая:

| `m` | `b` | `s × b` |
|---|---:|---:|
| `p` | 0 | 0 |
| `f` | 1 | +1 |
| `r` | 1 | −1 |

Това се реализира с логическа врата AND и разширение на знака.

## 6. Акумулатор (ACC)

### 6.1 Предназначение

Натрупва `V = Σ s(mᵢ) × bᵢ × 2^(n−1−i)` чрез отместване и събиране.

### 6.2 Ширина

За вход от `n` бита диапазонът е `[−(2ⁿ−1), +(2ⁿ−1)]`.
Необходима ширина на ACC:

| n | Диапазон | Минимална ширина на ACC |
|---:|---|---:|
| 1 | −1..+1 | 2 |
| 4 | −15..+15 | 5 |
| 8 | −255..+255 | 9 |
| 16 | −65535..+65535 | 17 |
| 32 | ±(2³²−1) | 33 |

Препоръчва се използването на поне `n+1` знакови бита.
В софтуера за безопасност използвайте `i32` или `i64`.

### 6.3 Поведение

```text
ACC ← (ACC << 1) + s × b
```

За всяка микростъпка:

| Микростъпка | Операция |
|---|---|
| `f` при `b=1` | ACC ← (ACC << 1) + 1 |
| `r` при `b=1` | ACC ← (ACC << 1) − 1 |
| `p` при `b=0` | ACC ← (ACC << 1) − 0 |

### 6.4 Реализация

```text
        ┌─────────────────────┐
        │   Регистър на ACC   │
        │    (n+1 бита)       │
        └──────────┬──────────┘
                   │
                   ▼
        ┌─────────────────────┐
        │ Отместване наляво 1 │
        └──────────┬──────────┘
                   │
                   ▼
        ┌─────────────────────┐     ±bit
        │ Суматор/изваждач    │◄────────
        └──────────┬──────────┘
                   │
                   ▼
        ┌─────────────────────┐
        │  MUX (зареждане на  │
        │       ACC)          │
        └──────────┬──────────┘
                   │
                   ▼
              (обратно към ACC)
```

**Сигнали:**

- `SHIFT = 1` (винаги, при всеки такт)
- `ADD = 1`, ако `m = f` и `b = 1`
- `SUB = 1`, ако `m = r` и `b = 1`
- `ZERO = 1`, ако `m = p` (без събиране или изваждане, само отместване)

Суматорът/изваждачът може да се реализира така:

```text
ACC_next = (ACC << 1) + (ADD ? +1 : SUB ? −1 : 0)
```

Тъй като `+1` и `−1` са константи, е достатъчно малко устройство за
увеличаване/намаляване, а не пълен суматор.

### 6.5 Алтернатива: директна претеглена сума

Вместо отместване и събиране може да се използва регистър за теглото:

```text
W ← 2^(n−1)   (начална стойност)
for each m:
    ACC ← ACC + s(m) × b × W
    W ← W >> 1
```

Този подход е концептуално по-прост, но по-бавен (по едно умножение на
стъпка). За хардуер се предпочита отместването и събирането.

## 7. Логика за управление

### 7.1 Входове

- `m` (2 бита от паметта за управление)
- `b` (1 бит от потока от битове)
- `clk`
- `reset`

### 7.2 Изходи

- `μPC_up`, `μPC_down`, `μPC_wait`
- `ACC_add`, `ACC_sub`, `ACC_shift`
- `WAIT_DONE` (състояние)

### 7.3 Машина на състоянията

```text
Състояния: IDLE, RUN, WAIT

IDLE:
    if reset: μPC ← 0, ACC ← 0
    else: → RUN

RUN:
    прочети m от control store[μPC]
    прочети b от bit stream[μPC]
    if m == p:
        ACC ← (ACC << 1) − 0
        → WAIT
    elif m == f:
        ACC ← (ACC << 1) + b
        μPC ← μPC + 1
    elif m == r:
        ACC ← (ACC << 1) − b
        μPC ← μPC − 1

WAIT:
    μPC ← μPC + 1
    → RUN
```

## 8. Времеви характеристики

### 8.1 Тактови цикли за микростъпка

| Микростъпка | Цикли |
|---|---:|
| `f` | 1 |
| `r` | 1 |
| `p` | 2 (1 пауза + 1 придвижване) |

### 8.2 Времева диаграма (пример `r p f`)

```text
clk:      1    2    3    4    5
          │    │    │    │    │
μPC:      3    2    2    3    4
          │    │    │    │    │
m:        r    p    p    f    —
          │    │    │    │    │
b:        1    0    0    1    —
          │    │    │    │    │
ACC:      0   −1   −2   −2   +2
          │    │    │    │    │
WAIT:     0    1    0    0    0
```

### 8.3 Пропускателна способност

За вход от `n` бита с `k` ненулеви бита:

- Минимум цикли: `n + k_p`, където `k_p` е броят на стъпките `p`
- Най-лош случай: `2n` (само `p`, всяка заема 2 цикъла)

## 9. Бележки за реализация върху FPGA

### 9.1 Оценка на ресурсите (`n = 16`)

| Компонент | LUT | Регистри |
|---|---:|---:|
| μPC (5 бита) | ~10 | 5 |
| Мултиплексор за знака | 2 | 0 |
| Умножител (AND) | 1 | 0 |
| ACC (17 бита) | ~20 | 17 |
| Машина на състоянията | ~15 | 3 |
| Общо | ~50 | 25 |

Изискванията са много малки. Побира се във всяка съвременна FPGA.

### 9.2 Критичен път

Критичният път е:

```text
μPC → Памет за управление → Мултиплексор за знака → Суматор на ACC → Регистър на ACC
```

При ACC с `n` бита суматорът е тясното място. При `n = 16`
увеличаването/намаляването изисква няколко LUT нива.

### 9.3 Препоръчителен процес за FPGA

- Напишете VHDL/Verilog или използвайте Amaranth/Migen (Python HDL).
- Тествайте с референтната реализация на Rust.
- Синтезирайте за малка FPGA (например iCE40 или ECP5).
- Сравнете използваните ресурси със суматор с допълнителен код.

## 10. Сравнение с хардуер с допълнителен код

| Компонент | Допълнителен код | MSPN |
|---|---|---|
| Суматор | пълен суматор с `n` бита | устройство за увеличаване/намаляване с `n+1` бита |
| Обработка на знака | неявна (MSB) | явна (мултиплексор за знака) |
| Отместване | не е необходимо | необходимо (отместване наляво при всяка стъпка) |
| Управление | просто | машина на състоянията със състояние WAIT |
| μPC | не е необходим (стандартен PC) | необходим (брояч на микропрограмата) |
| Пропускателна способност | 1 операция/цикъл | 1 бит/цикъл (по-бавно) |
| Латентност | ~1 цикъл | `n` цикъла |

Извод: MSPN е по-бавен от допълнителния код при паралелни аритметични
операции, но е по-бърз при последователни битови протоколи, в които
битовете пристигат един по един.

## 11. Отворени въпроси за хардуера

- Конвейерна обработка — могат ли няколко потока MSPN да споделят един ACC?
- Паралелен MSPN — могат ли `n` акумулатора да обработват дума паралелно
  с пренасяне между разрядите?
- Оптимизация — може ли състоянието WAIT за `p` да се премахне чрез
  предварително изчисляване на последователността?
- Енергия — каква е енергията на бит при MSPN спрямо допълнителния код?
- Троичен хардуер — как би се реализирало това върху естествено троична FPGA?

## 12. Обобщение

Хардуерът на MSPN се състои от:

- μPC — малък брояч нагоре/надолу със състояние WAIT
- Мултиплексор за знака — таблица за съответствие с 4 записа
- Умножител — една логическа врата AND
- ACC — регистър с отместване от `n+1` бита и устройство за увеличаване/намаляване
- Машина на състоянията — 3 състояния (IDLE, RUN, WAIT)

Общата цена на ресурсите е много ниска (~50 LUT и ~25 регистъра за
`n=16`). Дизайнът е достатъчно прост за FPGA прототип и достатъчно ясен
за формална спецификация.
