# 03 — Темпорален код: 7-те такта

## 1. Същност

Темпоралният код е последователност от 7 микростъпки, която се изпълнява за точно 7 процесорни такта. Той преобразува 2-битовите кодове в LUT реда в конкретни стойности на `B` и `T`.

| Параметър | Стойност |
|---|---:|
| Микростъпки | 7 |
| Тактове | 7 (по 1 на микростъпка) |
| Символи | `F`, `R`, `P` |
| Кодиране | 2 бита на символ |
| Първи 4 такта | Двоични тегла `8, 4, 2, 1` → `B` |
| Последни 3 такта | Троични тегла `9, 3, 1` → `T` |

## 2. Формат

```text
Такт:     1    2    3    4  │  5    6    7
Поле:    [B]  [B]  [B]  [B] │ [T]  [T]  [T]
Тегло:    8    4    2    1  │  9    3    1
Символ:  F/R/P F/R/P F/R/P F/R/P F/R/P F/R/P F/R/P
```

**Ключово:** Първите 4 такта винаги използват двоични тегла, а последните 3 — троични. Разделението е фиксирано: не зависи от стойностите, LUT реда или контекста.

## 3. Семантика на `F`/`R`/`P`

| Символ | Код | Знак `s` | Действие върху акумулатора | Действие върху MPC |
|---|---:|---:|---|---|
| `F` | `01` | +1 | Добавя теглото към текущата част | `MPC += 1` |
| `R` | `11` | −1 | Изважда теглото от текущата част | `MPC -= 1` |
| `P` | `00` | 0 | Не променя нищо | `MPC += 1` |
| `Q` | `10` | 0 | Не променя акумулатора | `MPC -= 1` |

**Забележка:** В каноничния LUT `Q` не се използва. Кодът `10` е резервиран и в текущия прототип се третира като грешка. Ако бъде активиран като `Q`, той ще позволява движение на MPC назад, без да променя акумулатора. Това само по себе си не прави целия кодек обратим.

В този модел `P` премества MPC с `+1`, вместо да го спира. Това се различава от „Ефективна дефиниция“ (секция 5), където `p` спира MPC.

## 4. Изпълнение

### Такт по такт

```text
За i от 0 до 6:
    m = microstep[i]          // 2-битов код
    s = decode(m)             // F→+1, R→−1, P→0

    ако i < 4:
        B += s * binary_weight[i]      // тегла: 8, 4, 2, 1
    иначе:
        T += s * ternary_weight[i−4]   // тегла: 9, 3, 1

    MPC = mpc_next(MPC, m)    // F→+1, R→−1, P→+1
```

### Псевдокод

```rust
fn execute(steps: &[MicroStep; 7], mpc: &mut u8) -> (i8, i8) {
    let bin_weights = [8, 4, 2, 1];
    let tern_weights = [9, 3, 1];
    let mut b = 0i8;
    let mut t = 0i8;

    for i in 0..7 {
        let s = match steps[i] {
            MicroStep::F => 1,
            MicroStep::R => -1,
            MicroStep::P => 0,
        };

        if i < 4 {
            b += s * bin_weights[i];
        } else {
            t += s * tern_weights[i - 4];
        }

        *mpc = match steps[i] {
            MicroStep::F => (*mpc + 1) % 27,
            MicroStep::R => (*mpc + 26) % 27, // -1 mod 27
            MicroStep::P => (*mpc + 1) % 27,
        };
    }

    (b, t)
}
```

## 5. Двете части: `B` и `T`

### Двоична част (тактове 1–4)

Теглата са позиционни двоични:

`8, 4, 2, 1 = 2³, 2², 2¹, 2⁰`

$$
B = \sum_{i=0}^{3} s_i \cdot 2^{3-i}
$$

**Свойство:** `B` е линейна комбинация от знаците. Може да се изчисли с маски (виж [02-lut.md](02-lut.md), секция 4).

### Троична част (тактове 5–7)

Теглата са позиционни троични:

`9, 3, 1 = 3², 3¹, 3⁰`

$$
T = \sum_{i=0}^{2} s_{i+4} \cdot 3^{2-i}
$$

Тук `s_{i+4}` е знакът на микростъпката с индекс `i+4`, тоест на тактове 5–7.

**Свойство:** `T` не е линейна комбинация в двоичен смисъл. Маските не работят — нужен е малък LUT или директно извличане на трите кода.

### Защо 4 + 3, а не друга комбинация?

| Комбинация | Стойности на `B` | Стойности на `T` | Контекст |
|---|---:|---:|---|
| 4 + 2 | 16 | 9 | Отрицателен (невалидно) |
| 4 + 3 | 16 | 27 | 0,755 бита |
| 4 + 4 | 16 | 81 | 2,34 бита (хибридността се губи) |

Само `4 + 3` дава положителен, но малък контекст. Това е единствената конфигурация, при която:

- `B` и `T` са съизмерими.
- 27-те двойки `(B, T)` са точно 27-те LUT реда.
- Контекстът е 1 бит (знакът), но носи само 0,755 бита информация.

## 6. Връзка с MPC

### Преместване на MPC за пълен цикъл

След 7-те такта MPC се е преместил с:

$$
\Delta MPC = n_F + n_P - n_R
$$

Всеки такт мести MPC, като `P` също го премества с `+1`, както `F`. Тъй като:

$$
n_F + n_R + n_P = 7
$$

получаваме:

$$
\Delta MPC = 7 - 2n_R
$$

Примери:

- Всички `F` (7 `F`): `Δ = 7` → MPC се премества с `+7`.
- Всички `R` (7 `R`): `Δ = 7 − 14 = −7` → MPC се премества с `−7`.
- Всички `P` (7 `P`): `Δ = 7` → MPC се премества с `+7`.
- 3 `F`, 4 `P`: `Δ = 7` → MPC се премества с `+7`.
- 4 `F`, 3 `R`: `Δ = 7 − 2·3 = +1` → MPC се премества с `+1`.
- 3 `F`, 4 `R`: `Δ = 7 − 2·4 = −1` → MPC се премества с `−1`.

**Важно:** В нашия модел `P` премества MPC с `+1`, а не го спира. Това се различава от „Ефективна дефиниция“ (секция 5), където `p` спира MPC. В каноничния LUT `P` е „пауза в стойността“, не „пауза в изпълнението“.

### Пример за движение на MPC

```text
MPC = 22 (LUT[22], микрокод F P F F F P P)

Такт 1: F → MPC = 23
Такт 2: P → MPC = 24
Такт 3: F → MPC = 25
Такт 4: F → MPC = 26
Такт 5: F → MPC = 0  (wrap)
Такт 6: P → MPC = 1
Такт 7: P → MPC = 2

Краен MPC = 2
```

## 7. Поведение на `P` — два аспекта

`P` има два аспекта, които не бива да се смесват:

| Аспект | Роля | Къде се реализира |
|---|---|---|
| Математически | `s = 0` → не влиза в нито една маска | В LUT кода (`00`) |
| Таймингов | Пауза от 1 такт | В управляващия автомат |

В каноничния LUT `P` не променя акумулатора, но премества MPC с `+1`. Това означава, че 7-те такта винаги напредват, независимо дали има `P`.

Алтернативен модел (не е нашият): `P` спира MPC (`halt`). Тогава 7-те такта не биха завършили, ако има `P`. Затова в нашия модел `P` е „пауза в стойността“, не „пауза в изпълнението“.

## 8. Обратимост на MPC и `Q`

### Кои действия са обратими?

По отношение на MPC `F` (`+1`) и `R` (`−1`) са взаимно обратни, когато се изпълнят на последователни тактове в рамките на един и същ 7-тактов цикъл: `F` мести MPC напред, а следващото `R` го връща на предишната позиция. Тук `i` означава позиция на такта в цикъла, а не позиция на MPC. Това не означава, че `F` и `R` са обратни за акумулатора.

Теглото за акумулатора зависи от номера на такта в 7-тактовия цикъл, а не от стойността на MPC. Затова `F` на такт `i` добавя `w_i`, докато `R` на непосредствено следващия такт `i+1` изважда `w_{i+1}`. Тези промени се компенсират само ако двете тегла са еднакви. Например, на тактове 1 и 2 в частта `B` теглата са 8 и 4: последователността `F`, `R` връща MPC назад, но променя акумулатора с `8 − 4 = 4`.

`P` също няма обратна операция за MPC в текущия набор от символи: той увеличава MPC с `+1`, без да променя акумулатора. За движение на MPC обратно е нужен `Q` (анти-`P`):

$$
Q: \quad s = 0,\quad MPC -= 1
$$

`Q` след `P` връща MPC на предишната позиция, без да променя акумулатора. Така `Q` осигурява обратимост на движението на MPC, но не и пълна обратимост на състоянието `(B, T, MPC)`, тъй като акумулаторните тегла зависят от позицията в цикъла.

Пълната обратимост на цялото състояние изисква схема, която отчита или съхранява предишната позиция и приложеното тегло. Това е извън обхвата на текущия прототип.

### Активиране на `Q`

`Q` може да използва резервния код `10`. В текущия прототип този код се третира като грешка; за да активира `Q`, са нужни:

- Промяна на декодера, така че да приема `10` като `Q`.
- Предефиниране на LUT-а и формата му, ако редовете трябва да използват `Q`.
- Тестове, които проверяват обратимостта на MPC.

За каноничния LUT в текущия прототип `Q` не е необходим.

## 9. Проверка на грешки

### Инвариантът

След изпълнение на 7-те такта винаги е изпълнено:

$$
|T + 2| = |B|
$$

Това е вградена проверка. Ако условието не е изпълнено, има грешка в:

- LUT реда (грешен микрокод).
- Изпълнението (грешен такт).
- Акумулатора (грешно начално състояние).

### Три кръстосани проверки

Тъй като `B` и `T` се изчисляват независимо (първите 4 такта срещу последните 3), има три нива на проверка:

1. **Вътрешна:** `B` и `T` от 7-те такта трябва да удовлетворяват инварианта.
2. **Срещу LUT:** `(B, T)` трябва да съвпадат с очакваните стойности за този LUT ред.
3. **Срещу диска:** `|B|` трябва да съвпада със стойността на нибъла, прочетен от диска.

Инвариантът е проверка за съгласуваност, но сам по себе си не показва къде е грешката. Сравняването с очаквания LUT ред и със стойността, прочетена от диска, помага да се стесни причината:

- Ако `|B|` не съвпада със стойността на нибъла от диска, провери четенето/декодирането на диска или целостта на данните.
- Ако `|B|` съвпада със стойността на нибъла от диска, но `(B, T)` не съвпада с очакваната двойка за избрания LUT ред, провери реда, микрокода и изчисленията на `B` и `T`.
- Ако `B` съвпада с очакваното `B`, но `T` не съвпада с очакваното `T`, провери извличането на последните три микростъпки и троичните тегла.

Ако двойката `(B, T)` съвпада с очаквания LUT ред, но инвариантът пак е нарушен, провери референтната таблица или самото изчисление на инварианта: за валиден LUT те не могат едновременно да са верни.

## 10. Работен пример

Нека изпълним `LUT[22] = F P F F F P P` с начален `MPC = 22`:

```text
Такт 1: F, тегло 8 (B)
  B += +8  → B = +8
  MPC: 22 → 23

Такт 2: P, тегло 4 (B)
  B += 0   → B = +8
  MPC: 23 → 24

Такт 3: F, тегло 2 (B)
  B += +2  → B = +10
  MPC: 24 → 25

Такт 4: F, тегло 1 (B)
  B += +1  → B = +11
  MPC: 25 → 26

Такт 5: F, тегло 9 (T)
  T += +9  → T = +9
  MPC: 26 → 0  (wrap)

Такт 6: P, тегло 3 (T)
  T += 0   → T = +9
  MPC: 0 → 1

Такт 7: P, тегло 1 (T)
  T += 0   → T = +9
  MPC: 1 → 2

Резултат: B = +11, T = +9
Проверка: |T + 2| = |11| = 11 = |B|  ✓
Краен MPC = 2
```

## 11. Резюме

```text
Темпорален код = 7 микростъпки × 1 такт = 7 такта
Първи 4 такта: двоични тегла 8, 4, 2, 1 → B
Последни 3 такта: троични тегла 9, 3, 1 → T
Символи: F (s=+1), R (s=−1), P (s=0)
MPC: F → +1, R → −1, P → +1 (винаги напредва)
Инвариант: |T + 2| = |B|
Обратимост на MPC: F↔R; Q (код 10) обръща P, ако бъде активиран
Пълна обратимост на (B, T, MPC): не се осигурява от Q; извън обхвата
```

**Ключово свойство:** Темпоралният код е атомарен — 7-те такта винаги се изпълняват заедно и не могат да бъдат прекъснати или изпълнени частично. Това прави проверката за грешки надеждна. Обратимостта на MPC е ясно дефинирана, но пълната обратимост на акумулаторите не се осигурява от текущия модел.
